## Purpose

The Cider Dashboard should not become a generic news feed.

The goal is a personalized second-brain command surface that helps Erik:

- curate the vault
- remember things he would otherwise forget
- resurface timely items from bookmarks, notes, projects, todos, events, media, and conversations
- expand on topics he already cares about
- discover similar items based on vault contents and taste signals
- see focused updates on teams, games, movies, shows, products, projects, and interests
- turn cards into Cider objects: bookmarks, notes, todos, events, reminders, memories, or project follow-ups

Good dashboard cards answer:

```text
What happened?
Why does this matter to me?
What vault item, taste signal, reminder, project, or interest caused this to appear?
What can I do with it?
Should Cider remember my reaction?
```

Bad dashboard cards are generic headlines with no personal connection.

---

## Product North Star

Cider should feel like a living, local-first second brain that watches the user's own context and brings the right thing forward at the right time.

Examples:

- Seahawks news because Erik follows the Seahawks, not because NFL news is trending.
- Mariners game cards because today has a game, a ceremony, or a standings implication.
- Movie sequel / adaptation updates because Erik has watchlist items, favorite franchises, or taste signals in the vault.
- Game updates because Erik bookmarked, played, wishlisted, or reacted positively to similar games.
- Project cards because a Cider plan, bug, stale doc, or agent run needs attention.
- Follow-up cards because a bookmark, note, or chat capture implies a reminder.
- Similar-item cards because the vault contains patterns like The Expanse, Fallout, Reacher/Lioness-style shows, Mariners/baseball, AI tools, Mac mini/local-first systems, vibe-coding, or co-op games.

The dashboard is not “news.” It is **personal context resurfacing + curated discovery + action routing**.

## Current Data Layer Shape

Current storage:

```text
/Users/minivish/CiderVault/.cider/dashboard/_cider_dashboard.json
```

Current top-level model:

```text
DashboardSnapshot
├── schemaVersion
├── topics: [DashboardTopic]
├── cards: [DashboardCard]
├── runs: [DashboardRun]
└── updatedAt
```

This is a good MVP foundation because it separates:

- **Topics**: user-facing lanes / interests
- **Cards**: surfaced items
- **Runs**: batches generated by an agent, collector, import, or manual seed

Current topic examples:

- Tech News
- Sports
- Cider Projects
- Entertainment
- Games

Current card fields already support the right direction:

- content: `title`, `subtitle`, `summary`, `whyItMatters`
- source: `sourceKind`, `sourceTitle`, `sourceURL`
- routing: `topicSyncIds`
- ranking: `priority`, `score`
- lifecycle: `status`, `createdAt`, `updatedAt`, `lastSeenAt`, `dismissedAt`
- feedback: `moreLikeThis`, `lessLikeThis`, `rating`, `feedback.updatedAt`

Keep `whyItMatters`. It is the difference between a generic feed and a useful second-brain feed.

## Recommended Model Direction

### Keep the Current MVP Core

The current `DashboardSnapshot -> topics/cards/runs` shape is healthy. Do not overbuild before the UI and user loop prove what is useful.

### Add First-Class Sources Later

For MVP, card-level source fields are fine:

```text
sourceKind
sourceTitle
sourceURL
```

Later, add source records when collectors become real:

```text
DashboardSource
- ciderSyncId
- kind: rss | bookmark | note | sports_api | steam | imdb | trakt | github | agent | manual | web_search
- title
- url
- enabled
- reliability
- lastFetchedAt
- lastSuccessfulFetchAt
- fetchCadence
- failureState
```

This lets Cider explain and tune where cards came from.

### Add Action State

Cards should become launchpads into Cider, not dead-end recommendations.

Potential action state:

```text
DashboardCardActionState
- openedAt
- savedBookmarkId
- savedNoteId
- createdTodoId
- createdEventId
- createdReminderId
- snoozedUntil
- archivedAt
- askAIThreadId
```

Possible actions:

- open source
- save as bookmark
- save as note / memory
- create todo
- create event
- remind me later
- snooze
- ask AI
- dismiss
- more / less like this
- mark stale / wrong / not relevant

### Add Personalization Debug Signals

`whyItMatters` is human-facing. Add machine-facing match data later:

```text
matchedSignals[]
- type: favorite_team | media_taste | vault_item | recent_capture | project | reminder | location | calendar | watched_item | wishlisted_game
- label
- sourceItemId
- confidence
```

Examples:

```text
favorite_team: Seattle Seahawks
media_taste: The Expanse / grounded sci-fi
vault_item: Wreck Runners TikTok bookmark
project: Cider Main Brain chat continuity
```

This helps answer “why did Cider show me this?” and improves learning.

### Add Freshness / Expiration

News and reminders need time semantics.

Future fields:

```text
publishedAt
relevantAt
eventDate
expiresAt
staleAfter
snoozedUntil
```

Examples:

- Mariners game card expires after the game unless archived as history.
- Movie sequel news remains relevant longer.
- Game patch/update cards may expire after a few weeks.
- Project stale-doc cards remain until dismissed, fixed, or superseded.

### Add Tags / Facets Separate From Topics

Topics are user-facing lanes. Facets are machine/use-case labels.

Example facets:

```text
sports
seahawks
mariners
game-update
movie-sequel
watchlist
vault-resurface
needs-action
local
high-confidence
```

A card can live in `Sports` but also carry `mariners`, `today`, `watch`, and `event` facets.

## Card Quality Rules

A dashboard card should be shown only when at least one of these is true:

1. **Timely:** something is happening now or soon.
2. **Personal:** it matches a known interest, team, project, media taste, bookmark, note, or conversation signal.
3. **Actionable:** Erik can save, watch, play, read, reply, plan, triage, or dismiss it.
4. **Resurfacing:** it brings back something useful from the vault at the right time.
5. **Discovery:** it is similar to something Erik likes or saved, with a clear reason.
6. **Maintenance:** it highlights stale, broken, messy, or unfinished Cider/vault/project work.

Avoid cards that are:

- generic trending news
- generic AI/productivity slop
- low-context headlines
- unsourced rumors
- repeated cards with no new information
- content that cannot explain why it matched Erik

## Example Card Lanes

### Sports

- Seahawks roster moves that matter, not every transaction.
- Mariners games, standings shifts, ceremonies, injuries, trade/signing news.
- “Watch tonight” cards only when timing matters.

### Games

- Updates for games Erik saved, wishlisted, played, or reacted to.
- Similar co-op, survival, MMO, or strategy games based on bookmarks and taste signals.
- Steam playtests, release dates, demos, major patches.

### Movies / TV

- Sequel, trailer, adaptation, renewal/cancellation, and release-date updates for known interests.
- Similar recommendations based on vault media libraries and taste notes.
- Co-watch suggestions tuned to Reacher/Lioness-style thriller/action energy.

### Cider Projects

- Active plan status.
- Stale docs or doc-rot.
- Recent agent runs.
- Bugs needing review.
- “Next best action” cards.

### Vault Curation

- Recent captures needing routing.
- Generic bookmarks that need title cleanup.
- Notes with obvious follow-up tasks.
- Duplicates, stale todos, forgotten events, unfinished ideas.

## Generation Philosophy

Dashboard generation should be conservative and explainable.

Pipeline shape:

```text
collect signals -> generate candidates -> score/rank -> explain why -> write cards -> learn from feedback
```

Signal sources can include:

- Cider vault bookmarks, notes, todos, events, contacts, files, boards
- media library Markdown pilots
- chat/session checkpoints
- explicit user preferences and feedback
- scheduled report-only agents
- external APIs/RSS/search for selected topics
- recent captures and open projects

Early agents should be report-only or reversible. Avoid silent destructive mutations.

## MVP Guidance

Good next steps:

1. Keep current JSON snapshot model.
2. Preserve topics/cards/runs.
3. Add richer card actions only when UI needs them.
4. Add `matchedSignals` and freshness fields before serious personalization.
5. Keep all cards explainable with `whyItMatters`.
6. Start with a few high-signal collectors:
   - local sports
   - Cider project/status
   - recent vault captures
   - media/game updates from explicit watchlist/bookmarks
7. Use feedback to tune, not just to decorate the UI.

Do not build a generic RSS dashboard and hope personalization appears later. The personal graph, vault context, and action loop are the product.
